# 入札ウォッチ 定期運用の手順

関連: [[CLAUDE]] / [[log]]

定期タスク `nyusatsu-watch-daily` は、このファイルの手順で動く。毎日10時30分ごろに実行される（Claude アプリが起動しているとき。閉じていれば次に起動したとき）。

## 0. 前提
- 作業場所: `C:\Users\Administrator\Projects\play\niche-news-sites`。コマンドは `site` フォルダで、`python -X utf8` で実行する。
- `CLAUDE.md` と、このファイルと、`plan/log.md` の最後の数件を読む。
- `git status` で、前回の作業の残り（コミットされていない変更）がないかを見る。あれば内容を確かめてから続ける。

## 1. 毎日：公告を集める
1. `python -X utf8 collect.py` を1回だけ実行する（直近7日分。問い合わせは2〜数回）。
2. エラーで止まったときは、続けて何度も実行しない。官公需情報ポータルサイトの規約で、同じサーバーから続けて大量にアクセスすることは禁止されている。エラーの内容を記録して終える。
3. 出力の「新規 N件」「件名がテーマに合う自治体の公告 N件」を控える。

## 2. 月曜だけ：週次ニュースの下書きを作る
月曜以外は、手順3へ進む。
1. `python -X utf8 draft_weekly.py` を実行する（前日の日曜までの7日間を集計する）。
2. `content/<日付>-weekly-it.md` と `data/reports/<日付>.json` を読み、表の件数と団体の内訳がファクト欄の数字と合っているかを確かめる。
3. 件名の一覧を見て、明らかにIT以外の案件（工事、測定機器など）が混ざっていれば、`queries.json` の `exclude_pattern` に語を足し、`python -X utf8 collect.py --reclassify` と `python -X utf8 draft_weekly.py --force` をやり直す。足した語は記録に書く。
4. 「## 注目の案件」に3件を書く（各件に「### 発注機関：要点」の見出し。公告日、件名と公告文の抜粋＝`data/reports/<日付>.json` の excerpt から分かることだけ。予定価格・期間などは公告文にあるときだけ書く）。手本は `_text/weekly_manual.py`。
   ミハルの見解（3〜4段落）を書き、`【要確認】` の目印をすべて消す。本文は3,000〜8,000字（check.py が数える）。過去の週の記事に、その週より後の出来事を書かない。
   - 一人称は「わたし」。です・ます調で、「正直、」「〜なんですよね」「個人的には」程度のくだけた言い回しを使ってよい。
   - ファクト欄にない数字は書かない。見解で使う事実（例：意見招請であること）は、ファクト欄に出典つきで足す。
   - 特定の団体・企業を責めない。件数の増減の理由を断定しない。
5. yomiyasu スキルで記事を推敲する（種類は article）。推敲前の本文を `_text/<日付>-src.md`、推敲後を `_text/<日付>-final.md` に置き、`yomiyasu_check.py run` と `verify` を実行してから記事に反映する。
6. `python -X utf8 check.py --all` でこの記事がエラー0件になること。`$env:INCLUDE_DRAFTS=1; python -X utf8 build.py` が通ること。
7. 手順2〜6がすべて通ったら `draft: true` の行を消して公開する（ユーザーの指示 2026-11-24「公開までやっちゃっていいよ」）。通らないときは draft のまま残し、理由を記録と完了報告に書く。
8. 公開した記事は、push のあと数分おいて https://pocketlog-note.github.io/nyusatsu-watch/ で表示を確かめる。

## 3. 記録とコミット
1. `plan/log.md` に、日付・取得件数（新規／テーマに合う自治体の公告）・作った下書き・気づいたことを1〜3行で追記する。
2. `git add -A` → `git commit`（メッセージは「何を・なぜ」を1行）→ `git push`。push すると GitHub Actions が点検とビルドをして GitHub Pages に公開する（公開リポジトリ `pocketlog-note/nyusatsu-watch`）。
   - コミットの作者は匿名アカウントの非公開用アドレス（リポジトリのローカル設定済み）。`git config --local user.email` が `...@users.noreply.github.com` でなければ push しない。
3. 完了報告は「何をしたか／確認できたこと／未確認のこと」に分けて短く書く。ユーザーの確認が要る下書きがあれば最初に書く。

## やってはいけないこと
- API への問い合わせを1回の実行で何度も繰り返すこと（`collect.py` の実行は1回まで）。
- 出典のない数字を記事に書くこと。架空のデータを実データの記事に混ぜること。
- 手順2の点検を通っていない記事の `draft: true` を外すこと。1回の実行で記事を2本以上公開すること。
- アカウント作成、X など外部への投稿（X は投稿文の下書き `site/x-drafts/` を作るところまで。投稿は人が行う）。
- `site/content/2026-11-23-hyojunka-1sha.md`（架空の数字のサンプル）を公開対象にすること。
- `git push --force` と履歴の書き換え。
